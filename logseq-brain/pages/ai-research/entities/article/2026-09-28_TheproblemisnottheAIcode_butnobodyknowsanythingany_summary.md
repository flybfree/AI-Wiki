# Summary: The problem is not the AI code, but nobody knows anything anymore

**Source:** [Simon Späti, “The problem is not the AI code, but nobody knows anything anymore”](https://www.ssp.sh/brain/the-problem-is-not-the-ai-code-but-nobody-knows-anything-anymore/)

## Summary

Späti argues that the main risk of AI-assisted coding is not simply the quality of generated code, but teams losing shared knowledge of their systems: why architectural choices were made, how components fit together, and who can maintain them. He describes a work culture in which people increasingly ask an AI coding assistant to produce code and project artifacts without enough time to read, review, or understand them.

## Key Takeaways

- **Generation can outpace understanding:** The article quotes an account of a team using Claude Code for specifications, code, tests, tickets, and reports while employees reportedly had little time to inspect the results. This is an anecdote, not a measured study.
- **Lower coding friction shifts the hard part:** Späti says product managers and people entering new fields may be able to build more with AI, while still making poor foundational choices when they lack domain, architecture, or system knowledge.
- **Maintenance remains costly:** More generated applications and pipelines still need debugging and maintenance. The author argues that system thinking, fundamentals, and understanding design intent remain important.
- **Human direction matters:** The piece contends that AI tools do not supply the user's intent or independently decide what should be built; people still need to guide the work and understand its context.

## Context

This is a personal commentary about AI coding tools and software-engineering practice. The central argument concerns AI-assisted code generation and its potential effects on knowledge, review, and maintainability—not a new model or a technical evaluation of coding agents.

## Implications

The author's perspective suggests that teams adopting AI code generation should preserve time for code review, architectural explanation, and maintenance, rather than treating generated code volume as the sole measure of progress. This is a practical interpretation of the essay, not an empirically established result.
