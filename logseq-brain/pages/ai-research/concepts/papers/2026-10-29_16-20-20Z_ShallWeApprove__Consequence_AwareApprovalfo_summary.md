## Summary
This paper introduces Caper, a novel consequence-aware approval mechanism designed to enhance the safety and reliability of autonomous coding agents. Unlike existing approvers that rely solely on static text analysis of proposed shell commands, Caper recognizes that command behavior is heavily dependent on the underlying code and workspace state. The core contribution is a pre-execution sandboxing approach where commands are tested in an isolated environment before approval, allowing for dynamic assessment of actual effects rather than predicted risks. This method significantly reduces harmful outcomes compared to traditional rule-based or model-based guardrails by providing approvers with concrete evidence of execution results.

## Key Contributions
- **Consequence-Aware Approval Framework:** The authors propose shifting from static text-based approval to dynamic, consequence-based evaluation. By pre-executing commands in a snapshotted sandbox, the system can observe actual side effects, such as file modifications or state changes, before committing them to the main workspace.
- **Bounded Reporting Mechanism:** Caper provides an independent approver with a bounded report of observed effects from the sandbox execution. This allows for informed decision-making based on empirical data rather than heuristic rules or language model predictions alone.
- **Rollback and Feedback Loop:** The system implements a robust rollback mechanism for blocked commands, providing the agent with actionable reasons for rejection. This enables the coding agent to adjust its strategy based on concrete failure modes rather than generic safety warnings.

## Methodology
The authors developed Caper as a pipeline that intercepts proposed shell commands from autonomous coding agents. Instead of immediately executing or rejecting them based on static analysis, Caper creates a snapshot of the current workspace state and executes the command within this isolated sandbox environment. An independent approver module then analyzes the "bounded report" generated by this sandbox execution, which includes details about file changes, system state alterations, and potential errors. If the command is deemed safe based on these observed consequences, it is committed to the main workspace; otherwise, it is blocked, rolled back, and a specific reason for rejection is returned to the agent. The authors evaluated Caper against six existing approval systems using two benchmarks: SABER and YoloFS-Ext, the latter being a new benchmark designed to hide harmful behaviors inside invoked tools.

## Results
Experimental evaluations demonstrate that Caper significantly outperforms existing safety mechanisms. On the SABER benchmark, Caper achieved a harmful-outcome rate of 6.7%, compared to at least 14.8% for competing systems. More critically, on YoloFS-Ext, a benchmark specifically constructed to test hidden risks within invoked tools, Caper reduced the harmful-outcome rate to 7.8%, whereas other systems failed with rates exceeding 35.3%. Additionally, Caper demonstrated high precision by blocking only 1.0% of "safe twins" (benign variations) of dangerous tasks in YoloFS-Ext, indicating that it effectively distinguishes between truly harmful actions and safe operations without excessive false positives.

## Significance
This work addresses a critical bottleneck in the deployment of autonomous coding agents: safety assurance. As agents gain autonomy, static guardrails become insufficient because they cannot predict complex interactions between commands and dynamic codebases. Caper’s approach offers a practical solution for real-world software engineering tasks where unintended side effects can cause significant damage. By providing actionable feedback to agents through rollback mechanisms, it enhances the iterative development process, making autonomous coding safer and more reliable for production environments.
