## Summary
JFrog Security researchers have exposed a wave of fabricated Critical CVEs targeting SQLite, revealing them to be "LLM slop" generated by artificial intelligence rather than genuine security flaws. Initial automated systems from the NVD and CISA incorrectly flagged these hallucinated vulnerabilities as critical threats, but rigorous manual verification proved that the cited code paths do not exist in the referenced versions and the provided proof-of-concept payloads fail to trigger any crashes. This incident highlights a significant failure in automated vulnerability intake processes and underscores the urgent need for human-in-the-loop validation when assessing AI-generated security advisories.

## Key Takeaways
- **Fabricated Evidence:** The advisories contained numerous factual errors, including references to non-existent functions like `exprComputeOperands()` in older SQLite versions and contradictory metadata, confirming they were AI-generated hallucinations rather than real bugs.
- **Automated Validation Failures:** Despite the lack of technical validity, major databases like the NVD initially assigned critical severity scores (up to 9.8) because they relied on automated ingestion without verifying the underlying code or testing the provided PoCs against isolated environments.
- **Corrective Actions Taken:** JFrog’s detailed audit forced a re-evaluation of these CVEs, leading Red Hat to downgrade the severity of at least one affected CVE from Critical (10.0) to High (7.6), demonstrating that human expertise remains essential for correcting systemic errors in vulnerability tracking.

## Context
This event illustrates the growing challenge of "AI slop" in cybersecurity, where large language models generate plausible-sounding but technically inaccurate content at scale. As organizations increasingly rely on automated feeds for threat intelligence, the volume of false positives generated by AI can overwhelm security teams and degrade the trustworthiness of critical infrastructure data. The SQLite case serves as a prime example of how generative AI can mimic the structure of legitimate technical reports while lacking the fundamental understanding required to verify code existence or memory management logic.

## Implications
The reliance on automated CVE assignment processes poses a severe risk to software supply chain security, potentially causing unnecessary panic, wasted remediation efforts, and erosion of confidence in vulnerability databases. Industry stakeholders must implement stricter validation protocols, including mandatory source code inspection and independent PoC testing, before accepting AI-generated advisories as authoritative. Furthermore, this incident emphasizes that while AI can assist in drafting reports, it cannot replace the critical thinking and technical verification provided by human security researchers, necessitating a hybrid approach to maintain the integrity of global security standards.
