## Summary  
The paper presents an experimental approach to solving the first thirty‑three exercises of the classic P‑99 Prolog problem set by prompting a large language model (Claude) and then rigorously verifying the generated code. By combining informal English specifications with automated generation, testing, and formal proof checking using LPTP, the authors demonstrate that LLM‑driven “vibe‑coding/vericoding” can produce reliable, executable Prolog programs while providing provable guarantees such as termination, uniqueness, existence, and functional correctness. The contribution is both practical (a reproducible workflow for generating and verifying Prolog code) and theoretical (showing how LLMs can be integrated into formal verification pipelines).  

## Key Contributions  
- [Finding 1] An LLM can autonomously generate the Prolog source files and corresponding test suites for a substantial subset of P‑99 problems, producing 58 procedures, 508 tests, and 257 lemmas.  
- [Finding 2] The generated programs are formally verified with LPTP to prove termination, uniqueness, existence, and functional correctness, yielding 11 800 proof lines that were manually inspected.  
- [Finding 3] The workflow exemplifies a “vibe‑coding/vericoding” paradigm where informal English specifications are transformed into executable Prolog code that is both generated by an LLM and validated through automated theorem proving.  

## Methodology  
The authors began with the English description of each problem, fed these prompts to Claude, and asked the model to output complete Prolog source files together with test programs. The resulting 1 180‑line codebase was manually reviewed for correctness. After manual checks, each logical statement produced by Claude was submitted to LPTP, which generated formal proofs that were then examined. This two‑stage process—LLM generation followed by human verification and automated proof checking—was repeated for all thirty‑three problems.  

## Results  
The experiment succeeded in solving the first 33 P‑99 problems without manual coding intervention. The LLM produced a total of 11 800 proof lines across procedures, tests, lemmas, and proofs. All generated files passed manual inspection, and LPTP’s formal proofs were validated as correct for termination, uniqueness, existence, and functional correctness. No counter‑examples or logical errors were found in the final codebase.  

## Significance  
This work proves that LLMs can serve not only as creative coding assistants but also as components of a rigorous verification pipeline. By integrating LLM generation with LPTP proof checking, the authors provide a template for “vericoding”—a systematic method that couples informal specification to executable, provably correct code. The approach may enable automated development of high‑level specifications where correctness is guaranteed through formal methods rather than exhaustive manual testing.
