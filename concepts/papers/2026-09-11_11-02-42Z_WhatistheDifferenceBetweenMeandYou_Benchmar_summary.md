## Summary
This research paper addresses a critical gap in the evaluation of AI coding assistants by shifting focus from mere functional correctness to the broader dimensions of code quality that influence long-term lifecycle costs. The authors conduct a large-scale comparative analysis involving over 787,000 function pairs across Python, Java, and C, contrasting human-written open-source code with implementations generated by three major AI models based on their docstrings. By characterizing structural complexity and statistical naturalness, the study reveals distinct qualitative differences in how AI-generated code is structured compared to human-authored software. Furthermore, the paper introduces CQBench, a new benchmark designed to facilitate rigorous quality assurance and security testing for future AI development.

## Key Contributions
- **Structural Compression and Stylistic Templating**: The study finds that AI-generated code is significantly more compressed than human-written code, typically being roughly half the size with fewer branches, leading to distinct clustering at the stylistic level despite functional equivalence.
- **Divergent Defect Profiles by Language**: Human code tends to concentrate issues typical of mature, complex codebases, whereas AI code exhibits repetitive boilerplate defects; notably, LLMs produce more severe security findings in Python and Java but fewer high-severity memory-safety vulnerabilities in C compared to humans.
- **Release of CQBench Benchmark**: The authors release a comprehensive benchmark consisting of 27,346 issue-prone tasks with established baselines and an evaluation pipeline, providing the community with standardized tools for assessing code quality and security beyond simple correctness metrics.

## Methodology
The researchers employed a large-scale empirical approach, mining human-written functions from open-source repositories across three major programming languages: Python, Java, and C. For each human function, they generated corresponding implementations using docstrings as prompts via three distinct AI coding assistants: OpenAI GPT models, DeepSeek-Coder, and Qwen2.5-Coder. This resulted in a dataset of 787,562 function pairs. The authors then characterized these code samples by measuring structural complexity and statistical naturalness. To contextualize the findings, they mapped static-analysis results onto established frameworks: Orthogonal Defect Classification for general defects and Common Weakness Enumeration (CWE) for security vulnerabilities. This methodology allowed for a direct, language-specific comparison of quality dimensions that dominate lifecycle costs.

## Results
The analysis revealed that AI-generated code is structurally compressed and stylistically templated, clustering distinctly from human code at the style level rather than just functionality. In terms of defects, human code concentrates on issues prevalent in mature codebases, while AI code suffers from repetitive boilerplate patterns. Security findings were found to be language-dependent; LLMs produced more severe findings in Python and Java but fewer high-severity memory-safety findings in C compared to humans. Crucially, once code size was controlled for, traditional complexity metrics carried little signal for distinguishing authors, whereas statistical naturalness proved effective at separating human from AI-generated code.

## Significance
This work is significant because it challenges the prevailing focus on functional correctness in AI coding evaluation, highlighting that quality dimensions affecting maintenance and security are fundamentally different between humans and AI. By identifying specific structural and stylistic gaps, it provides developers with insights into potential hidden costs of adopting AI-assisted development. The release of CQBench offers a vital resource for the research community to standardize quality assurance, ensuring future AI models are evaluated on robustness and security rather than just syntactic correctness.
