## Summary  
This paper introduces AkasicDB, a database system that natively integrates vector similarity search, graph traversal, and relational filtering into a single execution framework. By extending the prior Chimera project with native vector support, AkasicDB enables Omni RAG—a unified Retrieval‑Augmented Generation workflow that combines all three modalities without relying on out‑of‑DB pipelines. The authors demonstrate this capability through an interactive chat‑style demonstration that visualizes query execution and highlights the inefficiencies of existing database architectures. Their contribution is both a technical implementation and a practical showcase of how a unified DBMS can streamline complex RAG tasks.

## Key Contributions  
- AkasicDB provides a unified vector‑graph‑relational execution engine, eliminating the need for separate pipelines or in‑DB non‑native integrations.  
- The system introduces Omni RAG, the first native integration of vector similarity search, graph traversal, and relational filtering within one DBMS.  
- Experimental results show superior retrieval accuracy and reasoning quality over pure vector approaches while exposing latency overheads inherent to traditional database designs.

## Methodology  
The authors built on their earlier Chimera framework by embedding a vector index directly into the relational storage layer, allowing queries that combine similarity scores with graph‑based knowledge graphs. Queries are parsed into three parallel sub‑tasks—vector retrieval, graph traversal, and relational filtering—that run concurrently within AkasicDB’s execution engine. An interactive chat interface lets users type natural‑language questions; each response is generated by aggregating results from all three modalities and visualized on a diagram that traces the query path through the database.

## Results  
In benchmark queries involving 10 k vector documents, 5 k graph nodes, and 200 relational records, AkasicDB achieved an average retrieval F‑measure of 0.84 and a generation latency of 320 ms, compared with 0.71 F‑measure and 680 ms for a vector‑only system. The demo video (https://youtu.be/8d09_dtrEIM) illustrates the seamless flow from user input to multimodal answer generation.

## Significance  
AkasicDB bridges the gap between traditional relational databases and modern RAG pipelines, offering a scalable platform for applications that require both semantic similarity and structured knowledge. By integrating graph traversal and filtering natively, it reduces pipeline complexity and latency, paving the way for more robust, real‑world RAG deployments.

## Related Concepts  
- **Vector Retrieval**: Finding documents similar to a query using embeddings.  
- **Graph RAG**: Using knowledge graphs to enrich retrieval with relational facts.  
- **Filtered Vector Search**: Applying vector similarity results through additional filters.  
- **Chimera**: The earlier work that introduced multimodal data handling without native DB support.  
- **Omni RAG**: The unified workflow presented in this paper, combining all three modalities.
