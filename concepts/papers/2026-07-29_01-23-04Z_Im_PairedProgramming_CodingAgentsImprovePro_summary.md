## Summary  
This paper investigates the trade‑off between productivity and understanding when developers use AI coding agents such as Cursor. The authors argue that while these agents can speed up task completion, they may impair users’ ability to comprehend, extend, or communicate their code. To test this hypothesis, 54 students built a simple website using either an agent‑edited workflow or a pure‑human workflow with optional generic snippets. Their findings reveal that agents boost initial output but degrade comprehension and hinder future extensibility, while low‑effort prompting correlates with poorer understanding yet does not reduce user preference for the convenience of agents.

## Key Contributions  
- [Finding 1] Agents aid initial task completion but harm users' code comprehension and thus do not prepare users to extend their code.  
- [Finding 2] Low‑effort agent interaction types, like copy+paste prompts and auto‑accepted edits, are linked with lower comprehension.  
- [Finding 3] Despite self‑reported weaker understanding, users still prefer coding agents because they are quick and easy to use.

## Methodology  
The authors recruited 54 undergraduate students and presented them with a web development task that required creating a functional website. Participants were randomly assigned to one of two experimental conditions: (1) an AI editing system where the agent automatically modifies their code, or (2) a chatbot scenario where users write code alone or adapt generic snippets provided by the chatbot. Understanding was measured through comprehension questions and a follow‑up task in which participants had to extend the website’s functionality without any AI assistance. The study also collected self‑reported measures of perceived understanding and ease of use.

## Results  
The experimental results support all three findings. First, while agents produced functional code faster than human‑only coding, comprehension scores (as measured by quiz accuracy) were significantly lower for the agent group. Second, participants using low‑effort prompting strategies—copying prompts verbatim or accepting edits without review—scored even worse on comprehension tasks. Third, despite these comprehension deficits, a majority of users still preferred the agent because it reduced time and effort. The data indicate that productivity gains do not translate into improved long‑term understanding.

## Significance  
The study matters because it highlights an ethical risk in AI‑assisted development: rapid output can come at the cost of deep code comprehension, which is essential for maintenance, learning, and collaborative work. By showing that low‑effort prompting exacerbates this problem, the paper urges developers to design agents that encourage active engagement rather than passive acceptance.
