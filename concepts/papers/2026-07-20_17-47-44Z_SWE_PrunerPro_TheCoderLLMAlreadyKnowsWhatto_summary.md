## Summary  
The paper addresses the challenge of efficiently managing long code‑generation contexts for large language models (LLMs) by eliminating unnecessary tool output from the prompt. While prior work such as SWE‑Pruner inserts a separate classifier to decide what to keep, this approach adds latency and complexity. The authors propose **SWE‑Pruner Pro**, which directly tags each line of a tool’s response with a “keep” or “prune” label using the model’s own internal representations. By doing so, the model reduces prompt length without sacrificing task performance.

## Key Contributions  
- [Finding 1] The agent’s internal representations already encode relevance signals for code context, allowing pruning to be performed locally rather than via an external classifier.  
- [Finding 2] A lightweight “head” converts these internal embeddings into a per‑line keep‑or‑prune label, keyed by the line count of each tool output.  
- [Finding 3] SWE‑Pruner Pro reduces prompt and completion token usage by up to 39% across multiple benchmarks while maintaining or improving task quality.

## Methodology  
The authors embed a small classification head into two open‑weight backbones (e.g., LLaMA‑2‑7B, Falcon‑10B). For each line of a tool output, the model extracts its internal representation and passes it to an embedding table whose key is the line count. The resulting vector is compared against a threshold to produce a binary label. This process runs entirely within the inference loop, incurring only bounded overhead.

## Results  
Across four multi‑turn SWE benchmarks (MiMo‑V2‑Flash, MiMo‑V2‑Standard, Open‑Toolbench, and Code‑X), SWE‑Pruner Pro cuts total token consumption by an average of 39% compared with the baseline. Task accuracy remains unchanged or improves: on MiMo‑V2‑Flash the verified resolve rate rises to +3.8%, and Oolong’s long‑context score improves by +2.2 points. The method works across two backbones, demonstrating robustness.

## Significance  
Efficient context management is critical for scaling LLM applications to massive code corpora. By eliminating redundant tool output at the source, SWE‑Pruner Pro lowers latency, reduces memory pressure, and enables higher‑throughput inference—benefits that are especially valuable in production settings where token costs dominate.

## Related Concepts  
- **Pruning** – selective removal of data or tokens to reduce model size.  
- **Context management** – strategies for handling long input sequences.  
- **Code classification** – labeling code segments as relevant or irrelevant.  
- **Internal representations** – hidden embeddings that encode semantic meaning.  
- **Length‑aware embedding keying** – using token count as a lookup index.  
- **Tool output labeling** – per‑line keep/prune decisions generated by the model itself.
