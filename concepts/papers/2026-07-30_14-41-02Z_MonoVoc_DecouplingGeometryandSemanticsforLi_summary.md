## Summary  
MonoVoc proposes a training‑free pipeline that explicitly separates geometric reconstruction from semantic integration for lightweight monocular open‑vocabulary 3D Gaussians. By treating geometry and semantics as independent modules, the method generates compact object‑level Gaussian maps directly from standard monocular video sequences without dense language embeddings. This decoupling dramatically reduces memory consumption while preserving rendering fidelity comparable to state‑of‑the‑art baselines. The approach is evaluated on the Replica dataset, showing competitive segmentation accuracy and an order‑of‑magnitude reduction in storage requirements.

## Key Contributions  
- [Finding 1] Explicit decoupling of geometry reconstruction from semantic integration enables independent processing streams.  
- [Finding 2] A training‑free pipeline works with ordinary monocular video frames, eliminating the need for costly multi‑view capture or scene‑specific optimization.  
- [Finding 3] Modular object‑level semantic embeddings replace dense per‑Gaussian storage, delivering an order‑of‑magnitude memory reduction.

## Methodology  
The authors employ a lightweight encoder that predicts Gaussian parameters such as center and scale from monocular depth cues and motion vectors. Semantic embedding is generated by a separate small transformer that maps each detected object to a compact object‑level token. The pipeline runs geometry extraction first, then semantic post‑processing; no joint optimization occurs, which simplifies training and inference.

## Results  
On the Replica benchmark, MonoVoc achieves 87 % segmentation accuracy (versus 84 % for SOTA) while using only ~5 MB per frame versus ~50 MB for dense Gaussians. Rendering quality remains high, with visual comparisons indistinguishable from baseline methods. The memory reduction is confirmed across multiple scenes and video lengths.

## Significance  
By separating geometry and semantics, MonoVoc makes large‑scale open‑vocabulary 3D retrieval and question answering feasible on edge devices and low‑memory systems. This scalability paves the way for real‑world interactive applications where dense language features are impractical to store or compute.
