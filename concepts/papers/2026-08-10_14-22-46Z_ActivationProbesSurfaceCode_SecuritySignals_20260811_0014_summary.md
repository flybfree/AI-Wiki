## Summary  
The paper investigates whether the hidden security signals that an AI coding agent embeds in its internal activations can be recovered by a human reviewer who only has access to those activations, while the model’s own prompt‑based outputs miss them. By training a single linear probe on paired vulnerable and fixed Python functions, the authors demonstrate that activation values expose a code‑security signal with 61–67 % accuracy across five open‑weight reviewer models, outperforming both the 50 % chance line and the model’s own YES/NO win‑rate. This finding shows that prompting the same model for a written verdict—even with chain‑of‑thought reasoning—fails to differentiate vulnerable from fixed code because the underlying signal resides in activations rather than textual outputs.

## Key Contributions  
- [Finding 1] A linear activation probe can detect vulnerable functions above their fixed counterparts on 61–67 % of test cases for every model, indicating a statistically significant security signal.  
- [Finding 2] The probe’s performance exceeds the model’s own prompt‑based YES/NO win‑rate under identical prompts, proving that activations carry information not reflected in textual responses.  
- [Finding 3] Model activations encode a code‑security signal that is completely missed when the model is asked to produce a verdict, even with chain‑of‑thought prompting.

## Methodology  
The authors built a single linear probe per model on a curated corpus of Python function pairs where one version contains a known vulnerability and the other is its fixed counterpart. They then evaluated this probe on real disclosed vulnerabilities whose weakness type had never been seen during training, across five open‑weight reviewer models. No retraining was performed; only inference with the probe’s learned weights was used to compare activation scores.

## Results  
The probe correctly identified vulnerable functions above their fixes in 61–67 % of cases for each model, surpassing a random 50 % baseline. It also outperformed the model’s own YES/NO win‑rate on the same tasks under every prompt we tried. When asked to produce a written verdict—even with chain‑of‑thought reasoning—the model returned identical answers for vulnerable and fixed functions most of the time, confirming that the security signal is not encoded in textual outputs.

## Significance  
These results reveal that AI coding agents embed subtle security cues in their internal activations that are invisible to prompt‑based evaluation. This underscores a need for activation‑centric analysis when assessing the safety of code generated by closed‑weight models, especially as open‑weight reviewers become common tools for human oversight.
