## Summary  
This paper conducts a large‑scale replication of two earlier studies that examined whether code‑coverage and mutation scores correlate with the effectiveness of test suites generated by large language models (LLMs). The authors investigate how these proxy metrics behave in two common testing scenarios: regression‑style generation where the source code is assumed bug‑free, and bug‑exposure tasks where the underlying code may already contain defects. By comparing coverage, mutation, and real‑bug detection across a diverse set of LLMs, the study re‑examines the validity of relying solely on these proxy scores for evaluating LLM‑generated test suites.

## Key Contributions  
- [Finding 1] The usefulness of coverage and mutation is highly context‑dependent: they provide meaningful signals only when comparing models in regression‑style settings with assumed bug‑free code, whereas they become unreliable in bug‑exposure scenarios.  
- [Finding 2] Test suite size does not dominate the observed correlations among coverage, mutation, and real‑bug detection for LLM‑generated tests; other factors are more influential.  
- [Finding 3] The paper offers actionable guidance on interpreting prior results and recommends context‑aware evaluation rather than a one‑size‑fits‑all reliance on proxy metrics.

## Methodology  
The authors performed a replicability study by generating a wide variety of test suites using multiple LLMs across different codebases. They controlled for suite size and compared three outcomes: static code coverage, mutation score (how many bugs are caught), and real‑bug detection (actual defects uncovered). The experiments were split into two primary settings—regression‑style generation and bug‑exposure generation—to isolate the influence of each context on metric correlations.

## Results  
Empirical analysis shows that in regression‑style scenarios, coverage and mutation scores still correlate with model performance when comparing LLMs, suggesting they can act as useful signals. However, in bug‑exposure tasks, these metrics lose their predictive power; real‑bug detection remains the primary indicator of effectiveness. Moreover, systematic variation in test suite size had a minor impact on correlation strength, indicating that size is not the dominant confounding factor.

## Significance  
These findings challenge earlier assumptions that proxy metrics are universally reliable for LLM‑generated tests and highlight the need to consider the underlying code state when interpreting coverage or mutation scores. By providing clear guidance, the study helps researchers and practitioners design more robust evaluation pipelines that align with the specific testing objectives of their projects.
