# Training Compute-Optimal Large Language Models (Chinchilla)



**Source**: [Original Paper](https://arxiv.org/abs/2203.15556)
**Hoffmann et al., DeepMind / Google (2022)**
arXiv:2203.15556

## Abstract

We investigate the optimal model size and number of tokens for training a transformer language model under a given compute budget. We find that current large language models are severely undertrained.

## Key Concepts

### The "Undertrained" Discovery
After analyzing the scaling laws from Kaplan et al. (2020), the DeepMind team tried a radical experiment:

**Take GPT-3's compute budget but split it differently:**
- GPT-3: 175B parameters, 300B tokens (compute-heavy, data-light)
- Chinchilla: 70B parameters, 400B tokens (smaller model, MUCH more data)

**Result: Chinchilla OUTPERFORMED GPT-3 on every benchmark despite having 4x less compute.**

### The Optimal Ratio
The paper discovered the "sweet spot" ratio:
- For every 1 parameter, train on approximately 20 tokens of data
- GPT-3 used 1.7 tokens per parameter (vastly under-trained)
- Chinchilla used 5.7 tokens per parameter (closer to optimal)
- Following Chinchilla's ratio, you need smaller models trained longer, not bigger models trained less

### The "FLOPs-Optimal" Training Strategy
The paper formalized a training strategy:

| If you increase compute by... | You should... |
|------|------|------|---------|
| 2x | Double both model size AND data amount |
| 8x | Quadruple model size AND data amount |
| 1024x | Increase both by 32x |

This is a balanced, predictable recipe. No more "just make the model bigger."

### Practical Implications
- **Smaller models + more data > bigger models + less data** for the same compute budget
- Most modern models train with more data relative to their size than GPT-3 did
- The "chinchilla scaling" rule: **train smaller models longer on more data**

## Why This Changed Everything

### Overturned "Bigger is Better"
GPT-3 era thinking: "Make the model bigger."
Chinchilla era thinking: "Scale model and data together, with data getting slightly more weight."

This has guided every model since:
- PaLM (Google): Followed chinchilla scaling
- LLaMA (Meta): Followed chinchilla scaling
- Mistral, Qwen, DeepSeek: All follow the same principle

### The Data Quality Revolution
If data matters more than size, then:
- Data curation becomes critical (not just "collect more")
- Deduplication is essential (training on the same data twice doesn't help)
- Synthetic data quality matters (because synthetic data IS your data)
