## Summary
The paper investigates how large language models edit code that was originally generated by a different model with a distinct style. It finds that such edits are often excessive and may break functionality. The authors propose CROCODIL, a post‑training framework that reduces unnecessary changes while preserving correctness.

## Key Takeaways
- Models make more, and often excessive, edits on foreign code because they have differing stylistic preferences.
- CROCODIL uses a similarity reward to penalize large changes and an execution reward to ensure test success, combining both in its product metric.
- The framework is designed as a post‑training solution that can be applied without retraining the models.

## Context
The rapid adoption of multiple LLMs across development teams creates challenges when edits from one model affect code produced by another. This divergence can lead to inconsistent styles and functional regressions, highlighting a gap in current tooling for cross‑model collaboration.

## Implications
For developers, CROCODIL offers a practical way to maintain compatibility between models without sacrificing performance. For the industry, it suggests that future LLM ecosystems must incorporate mechanisms to harmonize edits across heterogeneous systems.
