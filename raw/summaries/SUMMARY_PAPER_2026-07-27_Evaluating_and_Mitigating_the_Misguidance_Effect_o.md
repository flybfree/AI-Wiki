## Summary
This paper investigates how buggy code influences the quality of unit tests generated by large language models. It introduces a metric called “misguidance effect” to quantify when LLMs produce tests that validate incorrect behavior instead of exposing bugs. The study shows that prompting with buggy code both increases misguided tests and reduces effective bug‑finding tests, indicating a twofold negative impact on test generation.

## Key Takeaways
- Prompting LLMs with buggy code leads to a rise in “misguided tests” that assert the same erroneous behavior rather than revealing it.  
- The same prompt simultaneously suppresses the creation of effective tests that would detect or fix the bug.  
- Internally, the model’s preference is skewed toward generating tests that reproduce the bug, confirming the misguidance effect.

## Context
The rapid adoption of LLMs for automated test generation has raised concerns about reliability when dealing with faulty code. Existing prompting strategies often assume clean input, which can mask the adverse effects of bugs on output quality. This work fills a gap by empirically measuring and addressing this hidden problem in AI‑driven testing pipelines.

## Implications
For developers integrating LLM test generators into CI/CD workflows, understanding misguidance is crucial to avoid false confidence in test coverage. Adopting specification‑based prompting can improve both the correctness and usefulness of generated tests across all code states, offering a practical mitigation strategy for real‑world software engineering.
