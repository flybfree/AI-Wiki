## Summary
This paper explores using large language models to automatically identify software weaknesses in the Autoware autonomous‑driving stack that could be exploited by attackers. By generating compile‑ready test artifacts with LLMs and then fuzzing them, the authors show that build integration issues dominate the workflow, preventing any weakness from being dynamically confirmed within a reasonable budget.

## Key Takeaways
- 80% of first‑shot compilation failures stem from dependency wiring problems rather than actual program logic flaws.  
- The reasoning model compiles 64% of harnesses on the initial attempt, compared to only 6% for the code‑specialized baseline model.  
- No candidate weakness is dynamically confirmed within budget; all observed crashes occur in stubbed code generated by the LLM.

## Context
The integration of AI tools into safety‑critical software development raises concerns about reliability and verification. This work demonstrates that even advanced LLMs struggle to produce fully executable artifacts for complex, interdependent systems like autonomous vehicles, highlighting a gap between candidate generation and practical validation.

## Implications
For industry practitioners, the findings suggest that automated testing pipelines must prioritize build‑time compatibility over raw AI output quality. The field needs more robust methods to bridge the gap between LLM‑generated test cases and executable verification, ensuring safety‑critical systems remain trustworthy.
