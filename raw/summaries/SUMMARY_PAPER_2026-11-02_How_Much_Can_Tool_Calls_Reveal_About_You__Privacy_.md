## Summary
This paper investigates whether tool-call traces generated by LLM-based agents interacting through the Model Context Protocol (MCP) can leak user profile information to external observers. The authors introduce PrivacyTrace, a benchmark of 1,000 synthetic user profiles and 4,000 agent trajectories across four domains, and demonstrate that tool-call traces enable a 26.25% attack success rate for user-profile inference—significantly above the 17.97% baseline from prior-based guessing—without any access to the user's actual conversations.

## Key Takeaways
- Tool-call traces serve as behavioral side channels: even without seeing user prompts or conversations, an observer can infer user attributes (such as profession, interests, or demographic traits) from the sequence of tool invocations, arguments, and returned results. The 26.25% attack success rate across four mainstream LLM attackers confirms this leakage is non-trivial and exceeds random guessing.
- Tool arguments and returned results are the primary evidence sources: the authors' analysis shows that the specific parameters passed to tools and the data returned by them carry the most discriminative signal for profiling. This means that even seemingly innocuous API calls (e.g., searching a restaurant database or querying a calendar) can encode sensitive user information.
- Cross-session linking amplifies profiling risk: connecting tool-call traces across multiple sessions or interactions significantly increases the accuracy of user-profile inference, suggesting that privacy risk compounds over time as agents accumulate behavioral history.

## Context
As LLM-based agents increasingly rely on standardized tool-interaction protocols like MCP to perform tasks such as web search, code execution, and database queries, the traces of these interactions are logged, stored, and potentially shared across services. Prior privacy research has focused on protecting user prompts and model outputs, but the intermediate tool-call layer—where arguments, function names, and return payloads are recorded—has received comparatively little scrutiny. This paper fills that gap by systematically quantifying how much user information leaks through the tool-interaction protocol itself, independent of the conversational content.

## Implications
For practitioners building agent systems, this work signals that privacy-aware design must extend beyond input/output filtering to include sanitization or anonymization of tool-call arguments, return payloads, and cross-session trace linkage. For industry stakeholders deploying MCP-based agents at scale, the findings motivate the development of privacy-preserving tool protocols, differential-privacy mechanisms for trace logging, and regulatory attention to behavioral side channels that users may not consciously recognize as data-sharing events. The open-source PrivacyTrace benchmark provides a reproducible evaluation framework for future privacy-hardening techniques in agent-tool ecosystems.
