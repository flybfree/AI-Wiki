## Summary
This paper introduces GenIaC‑SecBench, a benchmark that compares the security of Infrastructure-as-Code generated by large language models to that of human‑authored IaC using identical scanning tools. The study finds that model‑generated artifacts have higher vulnerability density than human templates when matched on declared resources, but the gap is bounded and varies with task complexity.

## Key Takeaways
- Vulnerability density is inversely related to artifact size (Spearman ρ = –0.55, p < 10⁻⁷⁷), indicating that comparisons often reflect size rather than true security differences.  
- When IaC artifacts are matched on the number of declared resources, model configurations produce vulnerability densities between 3.21× and 3.87× those of human‑authored code, with larger gaps for simpler tasks (e.g., 4.9× at one resource versus 1.4× at twenty or more).  
- Vendor “extended thinking” APIs improve model output by about 12 % over prompted chain‑of‑thought generation, while the latter is indistinguishable from standard generation.

## Context
The rapid adoption of large language models for infrastructure provisioning raises concerns that insecure defaults could be deployed at scale. Existing vulnerability counts lack a comparable human baseline, making it difficult to assess whether AI assistance actually degrades security or merely introduces new risks. This work provides a rigorous, size‑matched comparison essential for responsible model integration.

## Implications
For practitioners, the bounded nature of model‑human security differences suggests that LLMs can be used safely alongside human expertise without causing catastrophic breaches. However, the observed size‑related variance highlights the need for careful resource declaration and prompt engineering to keep vulnerability exposure low. The findings guide policy and tooling design toward more reliable AI‑assisted IaC workflows.
